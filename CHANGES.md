# Changes

This file lists what changed in each release of the plugin. It did not exist before; it starts with an Unreleased section, and a release moves what is under it to a heading with its version (the version itself is set as `docs/release-flow.md` says).

## Unreleased (the stage 4 candidate, on top of the stage 3 candidate)

**The Design view's box now has controls for the reading aids and the structure pieces.** Nothing here is released; the version is still 1.6.0.

- **A *Starts folded* switch** on a callout and on a group writes or takes off the `-` after the bracket, and nothing else. A callout written with a `+` says so in words (it starts open and can fold) and the switch turns the `+` into a `-`.
- **Hint and Solution fields under a question.** A question's box shows a title, a words box and a *Starts folded* switch for its hint and for its solution, with *Remove*, or *Add a hint* and *Add a solution* where there is none. They read and write the lines under the question and leave every other byte as it was, including a solution that stands right under the question's words with no blank line (adding a hint there and taking it out again gives the same lines) and a hint inside a group (the group's own `>` marks stay). A hint or solution that holds a list, a second callout or any other more than words keeps its title and switch, and its body stays in the Markdown with the reason in words. The reference linter warns about a hint or a solution written open, so turning the switch off draws that warning.
- **Pickers instead of text boxes.** An activity's `tab:` is a picker of its module's tabs, a page's `parent:` is a picker of the other pages of its tab (never itself or its own sub-pages; a loop is refused in words and nothing is written), and a copy button's `of:` is a list: one drop-down for each item, in order, with *Move up*, *Move down* and *Remove* and a drop-down that adds one at the end. A value the picker cannot offer (a tab that is not there, a parent that is not a page, a word of `of:` that names no question) is listed as *kept as written*, said in words, and is changed only when you choose something else; the last item of a copy button cannot be removed.
- **The kept entries' switch.** `entries:folded` on a repeating activity is a switch; on an activity that does not repeat it is off and says why; another value (`entries:open`) is kept as written and said, and replaced only by turning the switch on.
- **A module's notice is four fields** (*License*, *Copyright*, *Source*, *Version*). An absent field is added after the last line of the notice, a cleared one takes its line out, a line that is none of the four (such as `author:`) is listed as kept as written and never touched, a source that does not start with `http://` or `https://` is said to show as plain words, and a value that would break the line (a comment mark, quotation marks) is refused with the reason.
- **Pictures, figures and citations in the box of the words that hold them.** A picture has two fields, the words that describe it and where it is; for the reference style the place is the definition line elsewhere in the note, named by its line, and changing it writes that line. A remote address or a path that breaks the format's rules is kept as typed and warned about in words under the field (the linter warns too), never refused; a reference with no definition line says so and offers to add one. A figure's picker lists the diagrams the page can see and rewrites only the id inside the embed. A citation's five fields (*Source title*, *Edition or detail*, *Page or place*, *Quote*, *Verified date*) each change only their own piece of the definition line, and a value the reader's pattern would not read back is refused with the reason; a note outside the source pattern says so and stays words. Nothing is fetched or uploaded. A picture's description and its place are two fields, so changing both is two writes and two steps of Undo.
- **What stays Markdown:** a hint or solution that holds more than words, a picture, figure or citation shape the fields cannot read back (a file embed's description, a second embed's trailing words, a note over several lines), the contents of a diagram or a data block, the page break and the piece marker, and the row and the theme blocks (not in this stage).
- **As the rest of the box.** Each change is one write and one step of Undo, the kept-data guard asks where a change touches kept answers, and every control is at least 44 px on a phone. A drop-down is a field to the view, so Ctrl or Cmd with Z while a drop-down has the focus is left to the drop-down; after Esc it is the view's Undo.
- **Tests.** Real-Obsidian checks 86 to 95 (the fold switch, the pickers, the copy list, hint and solution, the notice, a picture, a figure, a citation, focus and Undo, and the phone), each also running the reference linter on the result, and the unit tests in `test/design-stage4*.test.mjs`.

## Unreleased (the stage 3 candidate)

**The Design view's box now has controls for the other kinds of question, and a small formatting bar for words.** Nothing here is released; the version is still 1.6.0.

- **A scale's anchors are rows.** Each anchor shows its number (the answer that is kept) and its words, with *Move up*, *Move down* and *Remove*, and an *Add an anchor* button. A word typed is applied when you leave it; each change is one write and one step of Undo. Rewording, renumbering or removing the anchor of an answer that is kept asks first; moving an anchor, or changing one nobody answered, asks nothing. A list that did not start at 1 keeps its blank line.
- **Number, text, date and lines have named settings.** *Smallest number*, *Largest number*, *Step*, *Big box*, *Earlier* and the rest are named in words, with the line's own word after. A value the format would not read (letters in a number, a decimal in a count of days) is refused: the status strip says why, the field goes back to what the note has, and nothing is written. -2 and 0.5 are accepted.
- **The each: setting is a picker.** It lists only what the question can really be asked for (the choices, multis and widgets of the activity, and the data blocks in reach), never the question itself; *Nothing: asked once* takes it off. With an answer kept, changing it asks first, and if you decline the picker goes back to what the note says (it used to keep the choice you had declined).
- **A listen's media is two controls.** The address and the name. An audio or video address is written as an embed and any other as a link; an embed with an address that is not media is refused with the reason. A media line the controls cannot show (written with a reference, in the middle of a sentence, or a second embed) is said in words and stays in the Markdown, unrewritten.
- **A widget's data block is a picker,** of the data blocks it can see, with the engine named, and *Open the data block* opens that block's own Markdown. The data itself (a JSON block) is never rewritten by a control. A widget line with no data block embedded is not drawn by the reader, so its picker has nothing to offer and it is fixed in Markdown.
- **A bar of four buttons for words** (*Bold*, *Italic*, *Link*, *Bullet list*) above a title, a description or a tip's prose, and the keys Ctrl or Cmd with B, I and K, and with Shift and 8 for bullets (prose only). It only writes the marks (`**`, `*`, `[words](https://)`, `- `): applying and removing it gives back the same bytes. With nothing selected it takes the word at the caret. A press on a button keeps the field's focus and selection, nothing happens in the id field or the Markdown box, a line that would turn into a rule or a link over several lines is refused with the reason in the status strip, and Ctrl+Z in the field takes back one step. On a phone the buttons are 44 px.
- **Nothing moves.** Pressing any of these controls leaves the header, the trail, the status strip, the scroll area and the box where they were, at a wide pane, at 740 px and on a phone.
- **A callout's box in the Paper looks** had control edges (the bar's buttons, the field rules, move and delete) at 2.9 to 1 in the light look and 2.4 to 1 in the dark look against the box's tint; they are now 3 to 1 or more.
- **Tests.** Real-Obsidian checks 78 to 85 (the pieces, the bar and keys, nothing moves, the phone and the looks) and the unit tests in `test/design-stage3.test.mjs`.

## 1.6.0

**The Design view's editor is rebuilt: the block opens as itself, and every change is saved as you make it.**

- **No Save, no Cancel, no draft.** The note on disk is the only truth. A change is written when a field is left (Tab, a click elsewhere), when Enter is pressed in a one-line field, or at once for a switch, a button or a choice, as one write and one step of Undo; a change that changes nothing writes nothing and records nothing. *Unsaved*, the armed Esc ("Esc again throws your changes away"), *Cancel*, *Save* and the live preview are gone, with their words. A change that would leave kept data not matching still asks first; declining writes nothing and the box shows the note again.
- **The block is drawn in place.** Its title and description are fields in the block's own type, its options, items and anchors are rows under them, its id, switches and values are a small strip with *Move up*, *Move down* and *Delete* at its end, and its Markdown is a section at the foot, closed until one press opens it (open at once for a block nothing else of which can be edited in place, with the reason). A press on the empty page, Esc, or Ctrl or Cmd with Enter applies what is typed and closes the block. (`design-edit.ts`, `design-rows.ts`, new `core/design-parts.ts`.)
- **A press right after typing is never swallowed.** Typing in a field and then pressing a button, another block, a switch or the header applies the typing and the press still lands: the box keeps its own elements across the write and is drawn again only when its shape changes. This is the class of defect beta.2 had, which only the real Obsidian shows; check 73 and the new check 75 press with a real mouse.
- **A write moves nothing on the screen.** The status line ("Changed Question: ...") has a strip of its own that is always there, so the first write after typing no longer pushes the page down between the mouse going down and coming up on a button. Found in the real app: the page jumped 41 px and the press was lost. Check 73 now measures the header, the page, the title, *Add an option* and the box before and after a write, with a short and with a long new title.
- **Selecting a block, and a message, move nothing.** The trail above the page is the page's own (the booklet, module, activity and tab down to it); it no longer gains the selected block as one more crumb, which wrapped to another line in a narrow pane and moved the page 20 to 45 px under a press (the selection is shown by the block and its bar). The status strip is exactly one line high (the line height of its own font size plus its padding and border), empty or with a message, and sits above the page, where the message used to cover the page's first line; a message too long for it is cut short and is whole in the strip's tooltip. Check 77 measures both with a real mouse in the real app, with long titles, in a wide pane, at about 740 px and at 390 px.
- **The rows and the Markdown read back the note.** After an option was moved or Undone, a row was left looking as if it were still being typed in, so a later removal or a Markdown edit was not drawn; the rows' words are now put into the rows by the box alone, which keeps what it last gave each control. A control also shows what the note has after its own write (a block whose Markdown typed in the box ends in lines that are another block's now shows its own lines). A block whose rows are refused opens its Markdown section (its reason points there), and the bar's *Edit as Markdown* opens it with the focus in it.
- **Typed text is never lost or hidden.** Opening another block or page, Undo and Redo, a switch to the Booklet or Markdown view, closing the pane and quitting all apply what is typed first. Text that could not be applied (the note changed on disk under it) stays in its field with the reason in words, and the first Esc says so and keeps the block open.
- **Undo and Redo, and they do not throw.** Typing is applied first, so the step undone is the typing's own; with nothing to undo or redo the status line says so; a step the note no longer matches (it was changed outside the view) is refused with the reason and stays on the stack; presses made at once never interleave or double-apply; with a question about kept data open they do nothing; whatever goes wrong becomes a line in the status line and the page is drawn from the note.
- **Tests.** The unit tests of the editor, rows, form, undo and canvas were rewritten for the new model; `test/design-parts.test.mjs` is new. In the real Obsidian checks 66 to 74 were rewritten or fixed for the new box, and two checks are new: 75 (the in-place flow with real keys and mouse) and 76 (Undo and Redo over twelve changes of mixed kinds, byte for byte, and the edges).

## 1.6.0, as built up in the betas (the Design view itself is still labelled a beta)

1.5.0 was never released: everything that was to be in it ships here, listed under *From 1.5.0* at the end. The manifest, `package.json` and `versions.json` go from 1.4.0 to 1.6.0, and `versions.json` has no 1.5.0 line.

**The Design view.** A booklet note can now open in a third view beside the Booklet view and Markdown. It is a beta.

- **Three modes, and a setting.** Each of the three views has header buttons for the other two. The new setting **Open booklets in** (*Booklet view*, the default, or *Design view*) chooses the view a booklet note opens in at each opening; a person who never chooses it sees no change, and no key is added to `data.json` until a choice is made. A pane left in the Design view is restored after a restart. The view type is `booklet-design`. (`design-view.ts`, `switch.ts`, `settings.ts`.)
- **The page and the outline (beta.2).** The tree is replaced by a left column with two tabs, *Outline* (a navigator: Settings, the booklet, modules, activities, tabs and pages, with the problems and leftovers at its foot) and *Add*, and a canvas that draws one page at a time as the format reads it (a module or tab with no pages is one page of its own, its child parts as cards), with a breadcrumb. Words go through Obsidian's renderer. A question of kind choice, multi, matrix, lines, text, number, scale or date, and a reading callout, is drawn as a reader sees it with nothing answered and every control switched off (nothing in a drawing can be pressed, and a drawing never shows or writes a reader's kept answer). Listen, widget and each questions, views and data blocks, the records, and text it cannot read are labelled cards with their Markdown as written. Media that points at another site is not drawn and nothing is fetched. Every line of the note still belongs to exactly one node, so the page logic reassembles the note byte for byte. (`design-view.ts`, `design-canvas-draw.ts`, `design-nav.ts`, `core/design-canvas.ts`, `core/design-tree.ts`, `design-sample.ts`.)
- **Add, by picture (beta.2).** All 56 parts are tiles with a picture (`design-art.ts`, drawn as data, no HTML strings), in a *Common* row and four foldable groups. Pick a tile and the places it can go light up; or tap a **+** between blocks and the *Add* tab opens with that spot chosen and only the fitting parts lit, and one tap places it; on a computer a tile can be dragged to a spot. Each rule still rests on a line of SPEC and a refused place says why. (`design-palette.ts`, `core/design-canvas.ts` `legalSlots`/`tileState`, `core/design-places.ts`.)
- **Hotkeys.** A first letter (`s q r v d`) picks a group and a second a part (shown as badges on the tiles), Enter places, Escape cancels. The keys are held in the view's own scope, never fire in a text field and win over a user's own bare-letter hotkey on the same key while the view has the focus; the palette commands (`design-add-piece` and `design-add-<group>`) have no default hotkey. (`core/design-keys.ts`.)
- **Move, delete, undo.** *Move up*, *Move down* and *Delete* on each block, each the smallest replacement of the note. A change that would leave kept answers, entries or rows not matching what they were kept for says how many and asks; it never blocks, and never deletes or rewrites the kept data. The view has its own *Undo* and *Redo* (buttons, Ctrl or Cmd with Z and Shift+Z while no field has the focus): a step is replayed only on the exact text it left behind, and is refused, with a reason, when the note was changed outside the view since. Writing goes into an open Markdown pane's editor, else `Vault.process`, the same path for the Booklet view. (`core/design-ops.ts`, `design-undo.ts`, `note-view.ts`.)
- **Edit in place, with a live preview (beta.2; the draft, *Save*, *Cancel* and the preview described here are replaced in beta.4, above).** Clicking a block opens it where it is: settings rows and a Markdown box edit one draft, with a preview of how a reader sees it. *Save* (Ctrl or Cmd with Enter) writes only that block's lines; *Cancel* drops the draft, Escape keeps it as unsaved and a second Escape throws it away; a note changed since it opened is refused as stale and the text kept. A floating bar on the selected block has *Move up*, *Move down*, *Edit as Markdown* and *Delete* (cards have their own). Undo and Redo return to the page and block a step was made on. On a phone (under about 700 px) the left column is a panel behind a menu button, with 44 px controls. (`design-edit.ts`, `design-canvas-draw.ts`, `core/design-form.ts`, `core/design-undo.ts`.)
- **The outline and the lines the reader cannot read moved into the view,** with the kept data that matches nothing now. The *Booklet blocks* panel keeps *Add a block*, *This line*, *Options* and *Data fields*. (`core/design-outline.ts`; `editor-outline.ts` is gone.)
- **Spanish and French.** The Design view's own words (core/design-strings.ts, English, Spanish and French) are in Spanish and French when Obsidian is; English is the source and the fallback, and `.localize-state.json` holds the hash of each English string for the next `/localize` run. A counted word has `.one` and `.other`; French takes 0 and 1 as the singular. **Still English:** the names of the parts (the pieces' labels), the hotkey group names and their descriptions, some of the reasons a part cannot go somewhere or a change touches kept data, the words inside a drawn sample, a block's setting names, the palette command names, and the Booklet view and the editing panel, which are English only. Found and fixed with the real Obsidian in both languages: on a phone the confirm dialog's longer title ended in an ellipsis and its question mark ran under the close button; it now wraps and keeps clear of it.
- **The page in Paper and petrol, light or dark, with a look selector.** The Design view's page (the canvas: what is drawn as a reader sees it, and the edit box that opens on a block) is drawn in the plugin's own look, the one the Booklet view takes, instead of Obsidian's theme. A dropdown *Look* in the header offers *Paper and petrol: light*, *Paper and petrol: dark* and *Obsidian*, so a writer can compare. It starts from the same look as a Booklet view (the setting *Booklet look*, else the one that matches Obsidian's light or dark mode, and it follows a change of mode until a look is chosen); a choice belongs to that view while it is open and is not saved. Only the page changes: the outline, the header and the trail stay in Obsidian's look, and *Obsidian* draws the page exactly as before. The rules are `themes/design.css`, built into `styles.css` with the other themes (check 74 of `e2e-tests/plugin-check.js`, `test/design-look.test.mjs`).
- **Saving no longer needs a click away first (beta.3; there is no draft or *Save* in beta.4, above).** In beta.2 what was typed in a settings row (a title, an id, a matrix anchor's number) reached the draft only when the box was left, so Ctrl or Cmd with Enter closed the block without saving the last typing, and the first click on *Save* only left the box and did not save. A row now remembers what is typed as it is typed and pays it into the draft before *Save*, Ctrl or Cmd with Enter, *Cancel* or Escape act, once and only once (the box's own redraw on leaving is not allowed to pay it a second time: the first version of this fix threw in the real Obsidian and was caught by check 73). *Save* and *Cancel* also take a press without first moving the focus, so the first click saves. (`design-edit.ts`, `design-rows.ts`, `design-view.ts`; check 73 and `test/design-editor.test.mjs`.)
- **A fix in the guard.** The data guard counted an activity's entries and drafts when the activity was deleted, but skipped the answers kept once for its questions (it did count them when the question alone was deleted). It now adds them, once per question id, and only where the id no longer stands in the module, so a renamed activity detaches none. (`core/editor-guard.ts`.)
- **Two defects found in the real Obsidian,** both fixed: a method named `dirty()` was shadowed by `TextFileView`'s own field of the same name, so opening the editor or deleting a block threw; and Obsidian's own default hotkey took Ctrl or Cmd with Enter before the editor's box could, so the view now holds that chord with a scope of its own while the box has the focus. The plugin's own buttons also beat Obsidian's button rule, which had left some of them cramped or overflowing.
- **Tests.** The Design view has its own tests in `test/design-*.test.mjs` and checks 64 to 77 of `e2e-tests/plugin-check.js` in the real Obsidian (the modes, the tree, the catalogue and keys, writes, the same writes with a Markdown pane, a phone's width, Obsidian in Spanish and in French, the row editors, typing then saving at once with real keys and clicks, and the looks).

**From 1.5.0 (never released).**

- **The editing panel.** The command **Booklet: Editor mode** (`booklet:editor-mode`), and a button on the Booklet view, open a *Booklet blocks* panel beside the note: add a piece at the cursor, and change the settings of the line the cursor is on. It writes through the note's Markdown editor, so, like any edit made in Obsidian's editor, a change from the panel saves the note with LF line endings. Before a change that your readers' saved answers or rows depend on, it says how many it touches and asks; it refuses an id rename the linter calls an error and a click in a code block that never closes. The panel's view type is `booklet-blocks`. Its words are English only.
- **A data block written in the note is not written past 5 MB.** SPEC section 5 ("What stops it") says the data is left alone when the changed file would be larger than a reader reads (5 MB); for data written in the booklet, the changed file is the booklet itself, measured whole in bytes (UTF-8, a byte-order mark counted) after the change. The plugin applied that limit only to data files. An edit, an added row or a removed row that would make the note larger than 5 MB is now kept as an entry but not written into the block, and the notice says so: "change kept, but not written to the data block, because the booklet would be too big to read (the limit is 5 MB)", or, for a row, "the row was kept but not added to the data block. That would make the booklet too big to read (the limit is 5 MB), so it was not changed." A change that changes nothing is not held to it. (`core/apply.ts` `applyInFence`, `view.ts`.)
- **Test cases shared with the browser reader.** `test/apply-vectors.json` and `test/pending-vectors.json` are copies of the Booklet repository's files of the same names, made by running this plugin's core; `test/shared-row-cases.test.mjs` runs every case against the plugin. See the README, "Shared test cases". `test/lone-cr.test.mjs` pins that a carriage return alone ends no line (front matter included), as in the renderer.
